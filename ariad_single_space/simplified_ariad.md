# 简化版 Ariad：单图 + 邻域扩张（去掉异步多副本机制）

## 1. 动机

原版单空间 Ariad（见 `ariad_single.py`）维护 `M` 份图 replica，并行异步刷新，用两种方式
决定何时把某个 replica 完全随机重置：

- **legacy**：固定周期，每 `R` 步重置一个（round-robin）。
- **maturity**：定期对 replica 做 exact-oracle recall 审计，够"成熟"（recall ≥ threshold）
  才允许被重置，且一次最多重置一个。

这套机制的设计初衷是：多份 replica 互相独立探索、periodically 随机重启一部分探索空间，
避免图搜索陷入局部最优、错过真正的近邻。

**实测发现**（`ariad_single_space_cluster_teacher` 下多组不同 N 的实验）：把 `M=1`、
`R` 设成远大于训练总 epoch 数（等价于整个训练过程只有 step 0 的初始化触发过一次"reset"，
之后再也不重置），也就是完全不给这份唯一的图做任何异步重启的机会，`match_true`
（模型邻居图对 ground-truth 的覆盖率）最终依然稳定收敛到 1。这说明：在当前这组任务/数据
regime 下，**异步多副本 + 周期性重置本身可能不是必要的**——单靠"局部邻域扩张 + 把上一轮
已经找到的邻居重新纳入候选（elite memory carry）"这一条链路，就足以让图搜索质量收敛。

因此这里把"没有 reset、没有多副本"这个特例，从"一组极端配置"提升为一个独立的、更简单的
算法版本：**去掉 replica 维度和所有 reset 相关逻辑**。

实现过程中发现一点：**elite memory carry 也可以一并去掉**，而不只是 reset。原版里 carry
的作用是"防止某个 replica 被 reset 之后，它之前找到的好邻居跟着丢失"——重置会把某个 replica
的当前邻居直接清成随机噪声，所以需要一份独立维护、不受 reset 影响的"最终图"（`cached_neighbors`）
作为安全网。但现在**没有 reset 事件**了，这张图的当前邻居 `O(i)` 永远不会被外力清空——而
"当前邻居 `O(i)` 本身"这一项，在每一步局部刷新的候选池里**本来就是无条件保留**的。精确打分下
"一个真正的 top-k 成员不会被更差的候选挤出 top-k"这个性质，只要它在候选池里，就自动成立
（因为能挤掉它的候选最多 k-1 个，否则它就不是 top-k 了）——`O(i)` 本身已经满足这个条件，不需要
再额外拼一份"上一轮的最终图"进来重复保护同一件事。所以最终版本：**去掉 replica 维度、去掉所有
reset 相关逻辑、也去掉 elite memory carry**，只保留局部邻域扩张。

## 2. 算法状态

只维护**一张图** `G`：`[n, k]` 的 LongTensor，`G[i]` 是节点 `i` 当前的 `k` 个近邻 id。

不再有：
- `M`（副本数）—— 没有副本，M 恒为 1。
- `R` / `reset_mode` / `maturity_*` —— 没有任何形式的整图或部分图随机重置。
- `ages` / `reset_ptr` / `maturity_log` / `lifetime_log` —— 这些都是服务于"何时重置谁"的
  簿记状态，机制本身不存在了，簿记也就不需要了。
- `final_carry_prev` / `cached_neighbors` —— elite memory carry 机制本身，见 1 节末尾的推理：
  没有 reset 之后它是可证明的 no-op，直接去掉。

保留：
- `k`（近邻数，即原来的 `k_replica` 和 `k_final` 合并成一个，因为没有 replica union、
  也没有单独的"最终图"这一步了——局部刷新选出来的 top-k 直接就是这一步的输出）。
- 反向缓冲 `k_rev`、局部扩张候选预算 `c_o2` / `c_i1` / `c_oi` / `c_rand`。

## 3. 初始化

```text
G <- 对每个节点 i，随机采样 k 个邻居 id（允许自环，后续打分阶段会被排除）
```

只有这一张图 `G`，没有第二份状态需要维护。

## 4. 每个训练 step 的刷新（用当前 embedding Z，无梯度）

不再区分"reset 的 replica"和"非 reset 的 replica"——每一步都对这唯一的一张图做同一套
局部刷新。

### 4.1 候选集来源（局部邻域扩张，跟原版完全一致，只是不再按 replica 分组）

对每个节点 `i`，本轮候选池由以下几部分拼接而成：

| 来源 | 含义 | 怎么采 | 预算 |
|---|---|---|---:|
| `O(i)` | 当前邻居本身 | 直接保留 | `k`（全部保留） |
| `O(O(i))` | 邻居的邻居（二跳前向） | 从 `O(i)` 随机挑一个锚点，再从锚点的 `O(·)` 里随机挑一个 | `c_o2` |
| `I(i)` | 反向邻居（谁指向我） | 取自反向缓冲区（对整张图重新构建一次，[见下方 4.3](#43-反向缓冲区-每步重建一次)） | `c_i1`（不超过 `k_rev`） |
| `O(I(i))` | 反向邻居的邻居 | 从 `I(i)` 随机挑一个锚点，再从锚点的 `O(·)` 里随机挑一个 | `c_oi` |
| 随机候选 | 全图随机采样 | — | `c_rand`（默认 0，可关） |

### 4.2 为什么不需要 elite memory carry

候选池里的 `O(i)` 这一项，直接就是"上一步的输出"（因为没有 reset，`G` 从不被外力清空，
下一步的 `O(i)` 必然等于上一步选出来的 `G(i)`）。精确打分下的 top-k 重选有一个单调性质：
一个候选只要出现在候选池里，且它是当前（全图范围）真正的 top-k 成员，就不可能被这个候选池
内的其他东西挤出 top-k——因为能挤掉它的候选最多 `k-1` 个，而"是 top-k 成员"这件事本身就
意味着全图最多只有 `k-1` 个东西比它分数高。`O(i)` 已经无条件在候选池里了，所以"已发现的真
邻居不会丢"这条性质已经被满足，不需要再单独拼一份"上一轮最终图"进来重复保护——原版的
elite memory carry 保护的是"某个 replica 被 reset 导致它的 `O(i)` 突然变成随机噪声"这一种
丢失场景，这里这种场景根本不存在。

### 4.3 反向缓冲区（每步重建一次）

`I(i)`（谁指向我）需要一个固定宽度 `k_rev` 的反向索引，从当前 `G` 重新构建：真实的入边
优先填充，宽度不够时用随机 id 补齐（避免入边稀疏的节点反向候选为空）。

### 4.4 重新打分 + 取 top-k

用当前 `Z` 对全部候选精确打分（`z_i · z_t`），然后做两步屏蔽：同一行内重复出现的 id
只保留一份（其余置 −∞，避免重复计数）；候选等于 `i` 自己的置 −∞（自环不占用 `k` 个
槽位）。最后取 top `k` 更新 `G`：

```text
G_new(i) = TopK_{t in 候选(i), t != i} z_i . z_t
```

注意：重复和自环候选是**先打分、后屏蔽**的，所以它们的点积确实被计算过，计入 9 节的
`C_scored`。

`G_new` 既是这一步之后维护的图状态，也直接是这一步训练前向要用的最终邻居——没有"局部
refresh 出来的图"和"最终输出图"这两层区分了（原版里这两层的区别本来就是为了给 replica
union 留出空间，M=1 时这个区分本来就没有实际意义）。

## 5. 伪代码

```text
init:
    G <- random_neighbors(n, k)

refresh(Z):                      # 每个训练 step 调用一次，Z 已 detach
    Rev <- build_reverse(G, k_rev)          # 4.3

    O   = G
    O2  = sample_forward(O, G, c_o2)        # 4.1 二跳前向
    I1  = Rev[:, :c_i1]                     # 4.1 反向一跳
    OI  = sample_forward(Rev, G, c_oi)      # 4.1 反向再前向
    Rnd = random(n, c_rand)                  # 可选

    cand  = concat(O, O2, I1, OI, Rnd)       # 每行宽度 C_scored，全部参与打分
    score = Z[i] . Z[cand]                   # 精确重打分
    score[duplicate ids in row] = -inf       # 行内去重
    score[cand == i]            = -inf       # 排除自环
    G     = topk(score, k)
    return G                                  # 本轮训练前向直接用这个

forward(Z):
    if 第一次调用: init，然后立刻 refresh(Z) 一次（不会把未打分的随机图交出去）
    elif 训练模式: refresh(Z)
    # eval 模式不刷新，直接复用训练前向留下的 G
    return G
```

## 6. 相比原版省掉了什么

- 不再需要 `M` 份图的存储、批量刷新（`_refresh_batched` 的 batch 维度 `B` 恒为 1）。
- 不再需要 replica union + 二次重打分这一步（原版 `_build_final` 把 `M` 份 replica 的候选
  并起来再选 top `k_final`；这里局部刷新选出来的 top-k 直接就是最终图）。
- 不再需要任何 reset 相关的状态、调度、日志（`ages` / `reset_ptr` / `reset_mode` /
  `maturity_threshold` / `maturity_gap` / `maturity_probe_size` / `maturity_log` /
  `lifetime_log` 全部消失）。
- 不再需要 elite memory carry（`final_carry_prev` / `cached_neighbors` 全部消失，见 4.2）——
  没有单独维护第二份"最终图"状态，也少一次候选拼接。
- 计算量和显存大致降为原版（同等 `k_replica`/`k_final` 设置下）的 `1/M`；每步的打分/dedup
  次数也从"局部刷新一次 + 最终融合再一次"变成一次。

## 7. 哪些是证明过的、哪些还只是经验观察

两件事的确定性程度不一样，分开说：

- **去掉 elite memory carry 是可以证明的**（4.2 节的单调性论证）：只要没有任何机制会清空
  `G` 的当前值（本版本确实没有），`O(i)` 本身就足以保证"当前真正的 top-k 成员不会在一次
  局部刷新里丢失"。这个结论不依赖具体任务、具体 N，只依赖"精确打分 + top-k 重选"这个数学
  性质，以及"没有 reset 事件"这个前提。

- **去掉 reset/多副本能收敛到 match_true=1，目前只是经验观察，不是理论证明**：这是在
  `ariad_single_space_cluster_teacher` 那组 cluster-local teacher 合成数据上、多次改变 N
  观察到的现象。它依赖候选池的局部扩张（二跳/反向）加上足够的训练 epoch 数，能够从随机
  初始化逐步"走到"真正的近邻——如果任务的近邻结构离随机初始化太远（比如 embedding 维度
  很高、真近邻非常稀疏、或者训练 epoch 数很少），纯局部扩张可能走不到，这时候原版"周期性
  随机重启部分探索空间"的价值可能重新变得必要。这里也还没有把"完全没有 reset"和"少量副本、
  但同样没有 reset 探索机制"这两种情况分开做消融——目前的证据只支持"`M=1` + 不 reset"
  这一个具体组合。

建议在真正把这个简化版本接入训练流程之前，至少在一个新的/更难的任务 regime 上复现一次
"收敛到 match_true≈1"的现象，再决定要不要把这个简化版正式替换掉原版 Ariad。

## 8. 附录A：候选路径消融——去掉 OI，预算转给 OO

在 4.1 节列出的四族局部扩张候选里，进一步做了一轮消融，测试 `I(i)`、`O(I(i))`、
`I(I(i))`、`I(O(i))` 这几条"基础池之外"的路径谁真正有用。用了两种互补的实验方式：

**A.1 只读诊断**（`candidate_path_ablation.py`，N=5000，150 epoch）：固定基础池
`B = O(i) ∪ O(O(i))`（`O(O(i))` 用当前配置的预算，不变），每个 epoch 用当前 embedding Z
分别给 `B+I(i)`、`B+O(I(i))`、`B+I(I(i))`、`B+I(O(i))`，以及对照组 `B+额外16个O(O(i))`
算四个指标：独有候选数 `|P\B|`、独有候选入选数、入选率、TopK 平均得分增益。这个诊断不改
真实训练，只是在真实训练产出的 `(G_prev, Z)` 上并行算了一份分析，不影响模型本身。

结果：
- `O(I(i))`、`I(I(i))`、`I(O(i))` 三条路径的入选率（0.02~0.08）和得分增益，全程都跟
  "直接再多撒16个 O(O(i))"的对照组**几乎没有可辨识差异**——尽管它们提供的"独有候选数"
  （11~14个/轮）比 `I(i)`（1~5个/轮）多得多，但候选多不等于候选好。
- 唯一表现出明显差异化价值的是 `I(i)`（反向一跳，"谁指向我"）：候选数量虽然最少，入选率
  全程最高且随训练推进还在升（0.25→0.34），得分增益比其余几组高一个量级以上。
- 所有路径的发现增益都随训练收敛单调递减——基础池本身覆盖得越好，留给任何额外路径去
  "新发现"的空间就越小。

**A.2 真实训练对比**（`real_ablation_oi_to_oo.py`，同一份 N=5000 数据、同 seed/初始化，
真实跑两组完整训练，非诊断）：

| 配置 | `c_o2` | `c_i1` | `c_oi` |
|---|---:|---:|---:|
| 原始 | 64 | 32 | 16 |
| 简化 | 80（64+从OI转来的16） | 32（不变） | 0 |

150 epoch 后对比（简化 − 原始）：`match_true` 两组都收敛到 1.0000（简化组约第80轮就到，
原始组约第120轮才到，反而更早）；`match_exhaustive` 全程简化组持平或略优（最终 epoch
+0.0036）；`mse` 只有最终一个 epoch 简化组略差（+0.00019），但此时两组 mse 都已在 1e-4
量级，且训练中段（epoch 30~120）反而是简化组更低，不构成一致的劣化趋势。

**结论**：`O(I(i))`/`I(I(i))`/`I(O(i))` 这几条经反向缓冲区衍生的二跳路径，无论是候选池
层面（入选率、得分增益）还是真实训练的最终任务指标，都没有比"单纯多给 O(O(i)) 一些预算"
表现出可辨识的额外价值；`I(i)`（反向一跳）则始终是最值的一条路径。因此**当前默认配置
已经去掉 `c_oi`（原16预算并入 `c_o2`），保留 `c_i1` 不变**（见 `ariad_train_single.py`
的 `ARIAD_CONFIG`：`c_o2=80, c_i1=32, c_oi=0`）。

这条结论目前只覆盖了这一组 cluster-local teacher 合成数据（N=5000, tau=0.5）；跟第7节
一样，如果之后要在明显不同的任务 regime 上继续用这个简化版本，建议至少复现一次"去掉 OI
不影响最终指标"这个现象，而不是直接假定它在别处也成立。

另外，附录 A 的两组实验是在 9 节所述的两处修改**之前**跑的：当时 `k=64`，并且打分时还没有
排除自环。结论（OI 没有可辨识价值）不依赖这两点，但如果论文要引用附录 A 的具体数值，
需要在当前配置下重跑。

## 9. 当前实现与配置（与论文单空间实验对应，2026-09 更新）

代码：`ariad_single.py`（`AriadSeekerSingle`），配置在 `ariad_train_single.py` 的 `ARIAD_CONFIG`。

| 参数 | 值 | 含义 |
|---|---:|---|
| `k` | 32 | 图宽度，也是注意力聚合的邻居数；与 teacher top-k 和评估宽度一致 |
| `k_rev` | 32 | 反向缓冲宽度 |
| `c_o2` | 80 | `O(O(i))` 候选数 |
| `c_i1` | 32 | `I(i)` 候选数（实际宽度为 `min(c_i1, k_rev)`） |
| `c_oi` | 0 | `O(I(i))`，已去掉（附录 A） |
| `c_rand` | 0 | 随机候选，关闭 |

**每行实际打分的候选数** `C_scored = k + c_o2 + min(c_i1, k_rev) + c_oi + c_rand = 32 + 80 + 32 = 144`。
`refresh()` 在运行时统计实际打分次数，写入 `last_refresh_stats["n_scored"]`（= N·C_scored），
论文里报告的就是这个实测值：`C_scored = n_scored / N`。

**相对早期版本的两处修改**（2026-09-26）：
1. **`k` 从 64 改为 32**，与评估宽度对齐。之前 `k=64` 时，match_true 衡量的是"16 个真邻居是否落在
   64 个邻居里"，比严格的 recall 宽松得多；"match_true 收敛到 1"的观察（第 1、7 节）是在那个
   宽松口径下得到的。k=32 时，即使是 Dense 和 Exact top-k，teacher match@32 也到不了 1。
2. **打分时排除自环**。之前第 3 节就写了"自环在打分阶段排除"，但代码实际上没有做：`z_i·z_i`
   通常很高，节点自己往往会占掉一个槽位（注意力里会被 mask，所以有效邻居只剩 k−1 个）。
   现在 `refresh()` 在去重之后把 `cand == i` 置为 −∞，与文档一致。

**评估时的一步滞后**：eval 模式不刷新图，复用训练前向刷新后的 `G`。这张图是用**更新前**的 `Z`
打分得到的，而评估用的是**更新后**的 `Z`，所以任何"ARIAD 图 vs 当前精确 top-k"的指标都包含一步滞后。

`n_scored` 计数，详见该文档第 10 节。
